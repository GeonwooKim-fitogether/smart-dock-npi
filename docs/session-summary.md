# 세션 보고 — Fitstack NPI 를 GitHub 로 옮기는 0단계 (2026-10-15)

> **결론:** GitHub 만으로 NPI 를 돌리는 데 필요한 **틀**은 만들어 브랜치 `feat/github-npi-roadmap` 에 커밋했다. 틀은 데이터 형식, 옮기는 스크립트와 시험, 추가 태스크 양식, 로드맵, 사용 가이드로 이뤄진다. 그러나 **내용**인 표준 태스크 83개, 단계별 통과 조건, Phase Review 규칙, 등급표는 옮기지 못했다. 기준 문서가 작업 폴더 밖에 있어 이 세션의 보안 설정이 읽기를 막았기 때문이다. Python 실행에도 승인이 필요해서 스크립트와 시험도 실제로 돌려 보지 못했다. 다음 주 시작까지 남은 선행 조건은 하나다. 기준 문서를 저장소로 들여와 옮기고, 처음으로 돌려 보는 것이다([로드맵](roadmap.md) 1단계).

## 요청과 결과

| 요청 | 결과 |
|---|---|
| 기준 문서(`fitstack-npi-reference.md`)를 먼저 읽는다 | **못 했다.** Read 도구와 셸 모두 "작업 폴더 밖"이라며 막혔고, 우회하지 않았다 |
| 1) `docs/roadmap.md` 로드맵 (Fitstack 자동 동기화는 맨 마지막) | 만들었다. 0~6단계이고, 6단계가 Fitstack 자동 동기화다 |
| 2) 라벨·마일스톤·이슈 양식·Phase Review 체크리스트로 옮기는 파일과 스크립트 (GitHub 에 실제로 만들지 않음) | 만들었다. 기본 동작이 미리 보기이고, GitHub 에는 아무것도 만들지 않았다. 데이터 내용은 비어 있다 |
| 3) `docs/how-to-work.md` 사용 가이드 | 만들었다 |
| 라이브 DB·Fitstack 은 건드리지 않는다 | 지켰다. 데이터베이스·Fitstack 도구를 한 번도 부르지 않았다 |
| 현재 브랜치에 커밋만, push·PR 은 하지 않는다 | 지켰다 |
| 결과 요약을 `docs/session-summary.md` 에 | 이 문서다 |

## 무엇을 만들었나 — 장치마다 확인 상태를 갈라 적는다

| 파일 | 하는 일 | 확인 상태 |

| `npi/tasks.csv` | 표준 태스크 목록 (`id,phase,title,role` 과 기준 문서의 나머지 칸) | 첫 줄만 있다 |

| `docs/roadmap.md`, `docs/how-to-work.md` | 로드맵, 사용 가이드 | README 의 상태 표와 폴더 목록에서 링크된다 |
| `README.md` | 상태 표 한 줄, 폴더 목록 두 줄 | — |
| `docs/lessons.md` | 이번에 부딪힌 체계 문제 두 건 (저장소 밖 입력, 실행 승인) | 규칙(교훈 백포트)에 따른 기록이다 |

만들지 않은 것도 적어 둔다.

- **Phase Review 이슈 양식은 만들지 않았다.** 단계마다 체크리스트가 달라 고정된 양식 하나에 담을 수 없다. 대신 스크립트가 단계마다 체크리스트가 채워진 심사 이슈를 하나씩 만든다.
- **자동 검사 워크플로는 더하지 않았다.** GitHub Actions 사용 시간은 유료이고, 늘리려면 사람의 승인이 필요하다([에스컬레이션 규칙](../.claude/rules/escalation.md) §2 의 5번).
- **단계 라벨은 만들지 않았다.** 단계는 마일스톤이 맡으므로, 같은 정보를 라벨로 한 번 더 두지 않았다.

## 확인한 것과 확인하지 못한 것

**확인한 것**

- 저장소 안 근거: 성공 기준 v2 에 이 제품의 등급이 `NPI-A` 로 적혀 있다. 성공 기준 v2 와 CEO 브리프에 Concept·Planning·Development 게이트가 나온다. README 에는 지금 "1 · Concept 진행 중, 통과 조건 4건 중 1건 충족"이라고 적혀 있다.
- 착수 전 대조: 원격 브랜치는 `main` 과 `docs/working-model` 둘이다. 후자는 2026-10-13 의 미머지 초안 "GitHub·Fitstack·Claude 운영 틀 v0.1"이고, 라벨·마일스톤·이슈 양식 준비를 체크리스트로 적어 이번 작업과 주제가 겹친다. 그 브랜치의 파일은 고치지 않았다. README 는 그 브랜치와 다른 줄만 고쳤다.
- 파일 등록부 검사(`file-registry.yml`)는 이 저장소에 등록부가 없어 아무것도 하지 않는다. 그래서 새 파일이 걸리지 않는다.

**확인하지 못한 것**

- 기준 문서의 내용 전부.
- 스크립트·시험·미리 보기의 실제 실행. Python 실행에 승인이 필요했고, 이 세션은 승인 창을 띄울 수 없었다.
- `gh` 의 실제 동작. 이 컴퓨터에 `gh` 가 설치돼 있는지도 확인하지 못했다(`gh --version` 도 승인 필요).
- 원격 최신 상태. `git fetch` 가 승인 필요라, 대조는 이 컴퓨터가 마지막으로 받아 둔 원격 상태를 기준으로 했다.
- 이슈 양식이 GitHub 에서 실제로 열리는지. main 에 머지된 뒤에만 볼 수 있다.

## 독립 검토

스크립트를 만들지 않은 검토자 한 명에게 실행 없이 코드를 읽어 반박해 보게 했다. 이 커밋 시점에는 검토가 아직 돌고 있어, 결과는 다음 커밋에서 이 절에 반영한다.

## 결정 큐 — 기본값을 정하고 진행한 것

모두 되돌리기 쉽다. GitHub 에 아직 아무것도 만들지 않았으므로, 데이터나 스크립트를 고치면 그대로 바뀐다.

| 결정 | 채택한 기본값과 이유 | 되돌리기 |
|---|---|---|
| 마일스톤 이름 | `N. 단계명` (예: `1. Concept`). GitHub 의 마일스톤 목록을 이름순으로 정렬해도 단계 순서대로 서게 하려고 | 쉬움 |
| 이슈 제목 | `[태스크 번호] 제목`. 다시 실행할 때 같은 태스크를 알아보는 열쇠이자, 나중에 Fitstack 과 짝짓는 열쇠다 | 쉬움 |
| 4·5단계 이름 | 미머지 초안의 `RTM`·`Launch` 를 임시로 넣고, 데이터에 "기준 문서로 확인"이라고 적었다. 성공 기준 v2 는 `Release` 라고 적었다 | 쉬움 |
| 등급 | `NPI-A` 는 Concept 부터 시작한다고 추론했다. 다른 등급은 비워 두었다 | 쉬움 |
| 미리 보기 형식 | 실제 실행과 똑같은 `gh` 명령을 그대로 보여 준다. 파일로 받을 때는 `--out` 을 쓴다(PowerShell 의 `>` 는 한글을 깨뜨린다) | 쉬움 |
| 연속 생성 간격 | 하나 만들 때마다 1초를 쉰다. GitHub 이 연속 생성 요청에 권하는 간격이다 | 쉬움 |

## 남은 것 (요청 범위 안)

1. **기준 문서를 저장소로 들여온다 (사람).** Windows 탐색기에서 `C:\Users\GeonwooKim\Dev\npi-reference\fitstack-npi-reference.md` 를 복사해 `C:\Users\GeonwooKim\Dev\smart-dock-npi\reference\` 에 붙여 넣는다. 그러면 탐색기의 `reference` 폴더에 그 파일이 보인다. 이것이 없으면 다음 주 시작이 막힌다.
2. **데이터를 옮기고 처음 돌린다 (다음 세션).** 표준 태스크 83개, 통과 조건, Phase Review 규칙, 등급표를 옮기고, 4·5단계 이름을 확인한다. 그다음 시험과 미리 보기를 돌린다. Python 실행 승인을 줄 수 있는 세션이어야 한다.
3. **push 하고 PR 을 연다 (지시가 있을 때).** 이번 세션은 지시대로 하지 않았다.
4. **PM 이 GitHub 에 깐다.** 머지한 뒤 `--apply` 를 실행한다([사용 가이드](how-to-work.md)).

## 참고 — 함께 발견한 것 (지시가 없으면 착수하지 않는다)

- **운영 틀 초안(브랜치 `docs/working-model`)과 정리가 필요하다.** 초안은 "NPI 단계·게이트 통과 여부의 정본은 Fitstack, GitHub 마일스톤은 이름만 맞춘다"는 입장이다. 이번 로드맵은 그 입장을 바꾸지 않고, 1~5단계 동안 Fitstack 에 손으로 옮기는 것을 기본값으로 두었다. 두 문서를 어떻게 합칠지는 로드맵의 "정해야 할 것"에 올려 두었다.
- **같은 체계를 다른 NPI 저장소에서도 쓴다면**, 스크립트와 양식의 원본을 창고(Template-repository)로 옮기는 편이 맞다([원본 우선 규칙](../.claude/rules/upstream-first.md)). 지금은 이 저장소에만 두었다.
- README 의 "지금 어디까지 왔나" 표 제목이 2026-10-13 기준이다. 이번에 더한 줄에만 10/15 를 적었다.

## 현재 상태

**현재 상태: 작업완료 직전.** 브랜치 `feat/github-npi-roadmap` 에 로컬 커밋까지 했다. 규칙 7-1 의 작업완료는 실행 확인과 push 까지를 뜻하는데, 실행 확인은 세션 권한 때문에 못 했고 push 는 지시대로 하지 않았다. 열린 PR 이 없으므로 브랜치 상태 이름(검토대기·보류)은 아직 붙지 않는다.

**배포완료까지 남은 것:** 위 "남은 것" 1~4, 그리고 PR 리뷰와 main 머지.
